title: Warum GPT-5 Codex plötzlich nur noch verspricht den Code zu ändern – aber nichts mehr passiert

---

In den vergangenen Wochen habe ich mich intensiv mit dem OpenAI Codex Agent in Visual Studio Code beschäftigt. Dabei ging es mir nicht darum, nur einmal kurz auszuprobieren, ob eine KI ein paar Codezeilen generieren kann. Viel spannender fand ich die Frage, wie sich ein moderner KI-Agent verhält, wenn er über längere Zeit an einem echten Projekt arbeitet.<br><br>

Als Modell kam <b>GPT-5.3 Codex</b> zum Einsatz, das ich in Azure AI Foundry bereitgestellt habe.<br>

Die ersten Erfahrungen waren tatsächlich beeindruckend. Der Agent konnte ein bestehendes Projekt analysieren, Zusammenhänge verstehen und mich bei der Fehleranalyse unterstützen. Er fand Stellen im Code, die ich selbst übersehen hatte, schlug sinnvolle Änderungen vor und konnte diese teilweise auch direkt umsetzen.<br><br>

Genau in solchen Momenten versteht man, warum das Thema KI-Agenten aktuell so spannend ist. Es fühlt sich nicht mehr wie eine klassische Code-Vervollständigung an, sondern eher wie die Zusammenarbeit mit einem technischen Kollegen.

Doch nach einigen längeren Sessions änderte sich dieses Verhalten.

Irgendwann trat immer häufiger eine Situation auf, die mich zunächst ziemlich verwundert hat. Der Agent analysierte ein Problem, erklärte ausführlich die Ursache und schrieb anschließend sinngemäß:

"Ich habe den Fehler gefunden und setze die Änderung jetzt um."

Dann wartete ich.

Und wartete.

Aber es passierte nichts.

Keine Datei wurde angepasst. Kein Tool wurde ausgeführt. Keine Änderung wurde vorgenommen.

Der Agent wusste offensichtlich, was zu tun war – aber der eigentliche Schritt zur Umsetzung blieb aus.

Wenn ich anschließend nachfragte, kam häufig eine Entschuldigung und die erneute Aussage, dass die Änderung jetzt durchgeführt wird. Doch auch danach blieb es manchmal wieder bei der Beschreibung.

Interessant wurde es dann, als ich irgendwann einfach nur noch "go" schrieb.

Plötzlich begann der Agent wieder zu arbeiten.

Dateien wurden geöffnet, Änderungen vorgenommen und die zuvor beschriebene Lösung wurde tatsächlich umgesetzt.

Auch Begriffe wie "run tools" oder "tool run" führten teilweise dazu, dass der Agent wieder in seinen ursprünglichen Arbeitsmodus zurückkehrte.

An diesem Punkt stellte sich für mich die Frage:

Warum funktioniert ein Agent, der gerade noch völlig autonom gearbeitet hat, plötzlich nicht mehr zuverlässig?

Was passiert technisch im Hintergrund?

Die Ursache liegt vermutlich weniger darin, dass das Modell "vergisst", wie man Code verändert. Vielmehr liegt es an der Architektur moderner KI-Agenten.

Viele stellen sich einen Agenten ungefähr so vor:

Frage → KI → Änderung am Code

In Wirklichkeit ist der Ablauf deutlich komplexer:

Benutzer
   ↓
GPT-5.3 Codex analysiert Problem
   ↓
Agent erstellt nächsten Schritt
   ↓
Tool-System prüft Aktion
   ↓
Datei wird geändert oder Befehl ausgeführt

Das Sprachmodell selbst besitzt keinen direkten Zugriff auf das Dateisystem. Es entscheidet lediglich, welche Aktion als Nächstes sinnvoll wäre. Die eigentliche Ausführung übernimmt die Agent-Umgebung in Visual Studio Code.

Genau diese Trennung ist wichtig, denn sie sorgt für Sicherheit. Ein KI-Agent darf nicht einfach jede beliebige Aktion auf einem Entwicklerrechner durchführen. Es gibt Kontrollmechanismen, Berechtigungen und Freigaben, die zwischen der Entscheidung des Modells und der tatsächlichen Änderung liegen.

Und genau an dieser Stelle kann das Verhalten entstehen, das ich beobachtet habe.

Der Agent kann den richtigen Lösungsweg erkannt haben, aber der Übergang von der Planung zur Ausführung funktioniert nicht immer sauber.

Ein weiterer Faktor ist meiner Meinung nach die Länge einer Unterhaltung.

Während einer intensiven Entwicklungsphase wächst der Kontext sehr schnell. Nach einigen Stunden befinden sich im Gespräch nicht nur die ursprüngliche Aufgabe, sondern auch:

frühere Fehlermeldungen
verworfene Lösungsansätze
bereits getestete Änderungen
Tool-Ausgaben
zusätzliche Anforderungen

Das Modell muss bei jeder Antwort neu bewerten, was der nächste sinnvolle Schritt ist.

Soll es noch analysieren?

Soll es eine Rückfrage stellen?

Oder soll es direkt ein Tool aufrufen?

Gerade bei langen Sessions scheint diese Entscheidung manchmal in Richtung Erklärung statt Ausführung zu kippen.

Warum hilft dann ein einfaches "go"?

Genau diesen Punkt fand ich besonders interessant.

Das Wort "go" ist natürlich kein spezieller Befehl, den der Codex Agent kennt. Es verändert aber den Gesprächskontext.

Der Agent bekommt eine neue eindeutige Information:

"Die Analyse ist abgeschlossen. Jetzt soll gehandelt werden."

Dadurch kann die interne Entscheidung für einen Tool-Aufruf wieder wahrscheinlicher werden.

Es ist also kein Zauberwort, sondern eher ein kleiner Impuls, der den Agenten aus einem Planungszustand wieder in die Ausführung bringt.

Sind das bekannte Probleme?

Bei meiner Recherche habe ich festgestellt, dass ich mit dieser Erfahrung nicht alleine bin. Andere Entwickler berichten ebenfalls davon, dass Coding-Agenten nach längeren Sitzungen manchmal eher erklären, was sie tun möchten, anstatt die eigentliche Aktion auszuführen.

Dabei muss man allerdings unterscheiden: Nicht jede dieser Situationen ist ein Fehler im eigentlichen Modell.

Das Verhalten kann durch verschiedene Faktoren beeinflusst werden:

die verwendete Agent-Version
die Konfiguration der Berechtigungen
Sicherheitsmechanismen
die Größe des Gesprächskontextes
die Entscheidung des Modells, ob ein Tool notwendig ist

Gerade diese Mischung macht die Analyse schwierig.

Meine persönliche Einschätzung

Trotz dieser kleinen Eigenheiten bin ich weiterhin sehr beeindruckt von den Möglichkeiten solcher KI-Agenten.

Was mich besonders fasziniert: Wir diskutieren heute nicht mehr darüber, ob eine KI Code schreiben kann. Wir diskutieren darüber, warum sie manchmal den letzten Schritt zur Umsetzung nicht automatisch macht.

Allein diese Tatsache zeigt, wie schnell sich die Technologie entwickelt.

Der Codex Agent ist für mich heute bereits ein sehr leistungsfähiger Entwicklungsassistent. Der nächste große Schritt wird sein, diese Systeme noch zuverlässiger über längere Zeit autonom arbeiten zu lassen.

Denn genau diese Fähigkeit entscheidet am Ende darüber, ob wir nur einen intelligenten Assistenten haben – oder einen echten digitalen Entwicklungspartner.

Fazit

Meine Erfahrungen mit dem OpenAI Codex Agent zeigen, dass KI-gestützte Softwareentwicklung bereits heute einen großen Mehrwert bietet. Gleichzeitig wird deutlich, dass zwischen Problemanalyse und tatsächlicher Ausführung noch technische Herausforderungen bestehen. Besonders bei langen Sitzungen spielen Kontext, Agent-Architektur und Sicherheitsmechanismen eine wichtige Rolle. Trotzdem bin ich überzeugt: KI-Agenten werden die Art und Weise, wie wir Software entwickeln, nachhaltig verändern.
